# notion-management

Notion を「思考 → 設計 → 実装 → 実行」まで一貫して管理するための個人用マネジメント基盤です。  
AI（ChatGPT）と対話して構造化した計画を JSON として出力し、Colab から Notion に厳密に反映する運用を前提としています。

---

## 目的

- 思考と実装を分離する（考える日 / 作る日を分ける）
- 中間ゴールを中心にした **永続的な開発ツリー** を作る
- Notion を「人間が判断しやすい構造」で使い続ける
- 登録作業・更新作業は極力 AI + コードで自動化する

---

## Master DB の役割

- **すべてを1つのDBで管理**
- ツリー構造は **self-relation（親ゴール）** で表現
- ジャンル / プロジェクトは「分類・可視化」のための軸

---

## Master DB プロパティ定義

| プロパティ名 | 型 | 用途 |
|--------------|----|------|
| タイトル | title | 表示名 |
| ジャンル | select | 開発 / 学習 など |
| プロジェクト | select または title | 投資OS など |
| 種別 | select | 設計ゴール / 中間ゴール / タスク |
| 親ゴール | relation（self） | ツリー構造 |
| ステータス | select | 未着手 / 進行中 / 完了 |
| 優先度 | select | 高 / 中 / 低 |
| 登録日 | date | 初回登録日（不変） |
| 完了日 | date | 完了時のみセット |
| 更新日 | date | Notion 側で自動更新 |

## 運用ルール（重要）

### 1. 登録順序は必須

**必ず上から順に登録する**

1. プロジェクト配下の「設計ゴール」
2. 設計ゴール配下の「中間ゴール」
3. 中間ゴール配下の「タスク」

※ 親が存在しない状態で子を登録するとエラーになる

---

### 2. 中間ゴールの考え方

- 中間ゴール = 「気づき・要求・モジュール追加」
- 例：
  - 小型株150億以下を監視したい
  - 前日との差分を見たい
- 実装は **必ずタスクとして分解**

---

### 3. apply_plan の思想

- AI が **構造化 JSON** を生成
- Colab から `apply_plan(plan)` を実行
- 既存ページは **title をキーに upsert**
- 登録日は保持、更新日は Notion 側で更新

---
